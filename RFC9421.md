# RFC 9421 Adoption

This document tracks adoption of RFC 9421 on the Fediverse.

## Background

Most [ActivityPub](https://activitypub.rocks/) servers implement HTTP Signature for authenticating server-to-server requests. The Fediverse community adopted an early version of [RFC 9421](https://datatracker.ietf.org/doc/html/rfc9421), [draft-cavage-12](https://datatracker.ietf.org/doc/html/draft-cavage-http-signatures-12), which is incompatible with the released version.

The [ActivityPub and HTTP Signatures Report](https://swicg.github.io/activitypub-http-signature/) outlines how HTTP Signatures and particularly draft-cavage-12 are implemented on the Fediverse.

Some Fediverse software has begun implementing the release version of RFC 9421, using [the double-knocking technique](https://swicg.github.io/activitypub-http-signature/#how-to-upgrade-supported-versions) suggested in the Report, or using other techniques.

This tracking document can help implementers debug their own implementation, as well as deciding when it's worthwhile to include RFC 9421 in their own servers.

## Adoption matrix

This matrix is for tracking server implementation status of RFC 9421. The table has the following columns:

* Software: name and link to the software. This is for server software only, not for libraries.
* Accept for GET: validates incoming signatures GET requests
* Accept for POST: validates incoming signatures for POST requests
* Send for GET: signs outgoing GET requests with RFC 9421; whether it uses double-knocking or another strategy
* Send for POST: signs outgoing GET requests with RFC 9421; whether it uses double-knocking or another strategy
* Issue(s): one or more bug-tracking issues for the topic of RFC 9421 upgrade. Preferably a tracking issue across the board.

Thanks to [FediDB](https://fedidb.com/software) for the seed version of the software list.
